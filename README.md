# 業務PCで生成AIを使うときの信号ルール

## 目的

業務PCから生成AI（チャット型AIエージェント等）を使うとき、会社の監視・情報漏れを防ぐための共通ルール。
前提：会社のPCやネットワークは記録されうる。「隠す」のではなく「入れない」で守る。

※ これは一般的な運用の目安。各社の情報セキュリティ規程・クライアントとの契約がこれと異なる場合は、そちらが優先。

## 最初に：このルールの考え方（3原則）

セキュリティが気になる人ほど、まずここだけ押さえてください。

1. **入れなかった情報は、どうやっても漏れない。** 監視ログにも、AIサービス側の保存にも、誤送信にも、そもそも載らない。これが一番強くて、設定やツールの仕様変更にも左右されない防御です。このルールの中心はこれです。
2. **会社の監視は「回避するもの」ではなく「前提にするもの」。** 業務PC・業務ネットワークの利用記録は、会社が正当な目的で取得しうるものです。記録を逃れる工夫（私物化・迂回）は、それ自体が規程違反になりえます。このルールは監視を前提に、記録されても問題ない使い方に寄せます。
3. **判断に迷ったら、一段厳しい方に倒す。** 🟡か🔴か迷う情報は🔴として扱う。「便利だから」で例外を作らないことが、事故を防ぎます。

## 想定している脅威と、このルールの効き方

| 脅威 | 何が起きるか | このルールでの対策 |
|---|---|---|
| 会社の監視・ログ | アクセス先URLや、環境によっては入力内容が記録される | 🔴は業務PCから入力しない。記録されても困らない内容（🟢／マスキング済み🟡）だけを業務PCで扱う |
| AIサービス側での保存・学習利用 | 入力した内容がサービス側に保存されたり、設定次第で学習に使われたりする | 🔴は「どの端末からも」入れない（後述）。サービス側の学習オプトアウト設定も併せて確認する |
| アカウントの乗っ取り・端末の紛失 | 第三者が履歴を見ると、過去の入力がまとめて漏れる | 履歴に🔴を残さない。アカウントは二要素認証を有効にし、業務PCにパスワードを保存しない |
| 貼り間違い・誤送信 | 機密を含む文書をそのまま貼ってしまうヒューマンエラー | 貼る前にマスキング＋目視確認を手順化する（後述のチェックリスト） |
| ダウンロードしたファイルの残留 | 完成品ファイルが業務PCに残り、共有・回収時に意図せず渡る | 機密を含む完成品は業務PCにダウンロードしない。ブラウザ表示のみにする |

## 信号ルール

### 🔴 絶対に入力しない（私用スマホ等、業務PC以外で扱う）

ここに挙げたものは、業務PCからだけでなく、**AIサービスへ入力すること自体を最小化**してください。端末を変えても、サービス側への保存という論点は残るためです。

- 顧客名・取引先名、IPアドレス、認証情報（ID／パスワード／APIキー）
- 契約で外部開示が禁止されている情報（訪問・入館の記録日など）
- 個人情報（利用者・患者・職員等の氏名と結びつく情報、健康情報）
- 未公開の経営数値・財務情報

どうしてもAIに相談したいテーマが🔴に触れる場合は、事実関係を抽象化して一般論として聞く形に置き換えます（例：特定の顧客の障害対応ではなく「Webサーバの接続上限に達した場合の一般的な切り分け手順は？」）。

### 🟡 マスキング済みなら入力可

- 社内文書・ソースコードの抜粋は、固有名詞と識別子を置換してから
  - 例：`[CLIENT_A]` `[IP_A]` `[SECRET_A]` のように、同じ値は同じプレースホルダーへ
  - 人物は実名・イニシャルではなく、対応表を別管理するコード（例：`S01`）を使う。小規模な組織ではイニシャル＋役職だけでも個人を特定できるため
- 置換した後も、貼る前に目視で1回確認する

#### マスキングの具体例

```
（悪い例）田中商事のサーバ 192.168.10.5 に token=abc123... で接続して、担当の佐藤さんに連絡
（良い例）[CLIENT_A] のサーバ [IP_A] に [SECRET_A] で接続して、担当の [S01] に連絡
```

#### マスキングの手順

1. 貼りたいテキストを、まず手元のメモ等に用意する（いきなりAIの入力欄に貼らない）
2. 固有名詞・IP・認証情報・人名をプレースホルダーに置換する。置換の対応表（実名⇔コード）はAIには渡さず、手元でのみ管理する
3. 置換漏れがないか、目視で1回通読する。特に「文脈から推測できる情報」（珍しい役職名＋小規模組織、具体的な日付と出来事の組み合わせ等）が残っていないかを見る
4. 問題なければ貼る。AIの回答に含まれるプレースホルダーは、受け取った後に手元で実名へ戻す

※ マスキングは漏洩リスクを大きく下げますが、完全ではありません。文脈から推測されうる情報や、そもそも外部に出してはいけない契約情報は、マスキングしても扱わないでください。

### 🟢 そのまま入力可

- 一般的な技術の質問、公開情報の調査
- テンプレート・資料の型づくり、固有名詞を含まない議論や文章の下書き

## 使い方の型

- 業務PCは「窓口」だけにする：アプリは入れずブラウザで使う。機密を含む指示・議論はスマホ側で行い、業務PCは完成品の閲覧と🟢の入力専用
- 機密を含む完成品は業務PCにダウンロードしない（ブラウザ表示のみ）
- 生成AI側の設定も確認する：会話が学習に使われる設定があるサービスでは、オプトアウトの有無を確認する

## アカウントと端末の衛生（あわせて実施）

- 使うAIサービスのアカウントでは**二要素認証を有効にする**。履歴＝過去の入力の集合体なので、アカウント防御がそのまま情報防御になります
- 業務PCのブラウザに、個人のAIアカウントのパスワードを保存しない。使い終わったらログアウトし、タブを閉じる
- 離席時は画面ロック。チャット画面を開いたまま席を離れない
- 業務PCにダウンロードしたファイルは、不要になったら削除する（特に🟡相当の内容を含むもの）
- 会社の支給アカウント／法人プランがある場合はそちらを優先する。契約上、入力データの取り扱いが明確なことが多いためです

## よくある不安への回答

**Q. この使い方をしたら、会社に利用が分かりますか？**
A. 分かる前提でいてください。アクセス記録は残りえます。このルールの目的は「隠すこと」ではなく「記録されても情報漏洩にならない使い方をすること」です。そもそも会社の規程で外部AIの利用自体が禁止されている業務では、使わないでください。

**Q. AIに入れた情報は学習されて、他の人の回答に出たりしませんか？**
A. サービスと設定によります。だからこそ、このルールは設定に依存しない防御（🔴は入れない）を中心にしています。あわせて、各サービスの「学習に使わない」設定（オプトアウト）や法人向けプランのデータ取り扱い条件を確認してください。設定項目はサービスごとに変わるので、利用開始時に公式の案内で確認するのが確実です。

**Q. マスキングすれば、何でも貼って大丈夫ですか？**
A. いいえ。マスキングは「識別子を消す」対策で、内容そのものの機密性は消えません。契約で外部開示が禁止されている情報、個人の健康情報などは、マスキングしても入力しないでください（🔴）。

**Q. 私用スマホからなら、🔴を入れても大丈夫ですか？**
A. 会社の監視という論点は外れますが、AIサービス側への保存・学習という論点は残ります。🔴は端末を問わず最小化し、必要な場合は抽象化して一般論として相談する形を推奨します。

**Q. うっかり🔴を入力してしまったら？**
A. 隠さず、速やかに対処してください（次項）。やってはいけないのは、証跡を消そうとしてさらに操作することと、報告しないことです。

## 万が一、機密情報を入力してしまったら

1. そのチャット（履歴）を削除する
2. 認証情報（パスワード／APIキー）を入れてしまった場合は、**直ちにその認証情報を無効化・再発行する**。削除よりこちらが先です。「見られた前提」で動きます
3. 会社の情報セキュリティ担当・上長へ報告する。何を・いつ・どのサービスに入力したかを正確に伝える
4. 顧客との契約に関わる情報の場合は、契約側の報告手順に従う

## このルールの限界（正直なところ）

- このルールはリスクを大きく下げますが、ゼロにはしません。最終的な安全性は、各社の規程、各AIサービスの規約・設定、その時々の運用に依存します
- AIサービスの仕様（保存期間、学習利用、設定項目）は変わることがあります。大事な利用の前に、公式の案内で現行の取り扱いを確認してください
- 判断に迷うケースが続くようなら、ルールを各自で拡張せず、情報セキュリティ担当に確認して共通ルール側を更新してください
