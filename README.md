# 業務PCで生成AIを使うときの信号ルール

## 目的

業務PCから生成AI（チャット型AIエージェント等）を使うとき、会社の監視・情報漏れを防ぐための共通ルール。
前提：会社のPCやネットワークは記録されうる。「隠す」のではなく「入れない」で守る。

※ これは一般的な運用の目安。各社の情報セキュリティ規程・クライアントとの契約がこれと異なる場合は、そちらが優先。

## 信号ルール

### 🔴 絶対に入力しない（私用スマホ等、業務PC以外で扱う）

- 顧客名・取引先名、IPアドレス、認証情報（ID／パスワード／APIキー）
- 契約で外部開示が禁止されている情報（訪問・入館の記録日など）
- 個人情報（利用者・患者・職員等の氏名と結びつく情報、健康情報）
- 未公開の経営数値・財務情報

### 🟡 マスキング済みなら入力可

- 社内文書・ソースコードの抜粋は、固有名詞と識別子を置換してから
  - 例：`[CLIENT_A]` `[IP_A]` `[SECRET_A]` のように、同じ値は同じプレースホルダーへ
  - 人物は実名・イニシャルではなく、対応表を別管理するコード（例：`S01`）を使う。小規模な組織ではイニシャル＋役職だけでも個人を特定できるため
- 置換した後も、貼る前に目視で1回確認する

### 🟢 そのまま入力可

- 一般的な技術の質問、公開情報の調査
- テンプレート・資料の型づくり、固有名詞を含まない議論や文章の下書き

## 使い方の型

- 業務PCは「窓口」だけにする：アプリは入れずブラウザで使う。機密を含む指示・議論はスマホ側で行い、業務PCは完成品の閲覧と🟢の入力専用
- 機密を含む完成品は業務PCにダウンロードしない（ブラウザ表示のみ）
- 生成AI側の設定も確認する：会話が学習に使われる設定があるサービスでは、オプトアウトの有無を確認する

## チェックリスト（入力前に10秒）

- [ ] 🔴の情報が混ざっていないか
- [ ] 固有名詞・IP・認証情報をプレースホルダーに置換したか
- [ ] 人物はコード表記になっているか
- [ ] 会社の規程・顧客との契約で、そもそも外部AI利用が禁止されていないか
